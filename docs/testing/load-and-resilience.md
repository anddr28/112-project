# Нагрузка и отказоустойчивость — итоги

Стенд: Apple M4 (10 ядер, 16 ГБ), Docker Desktop, PostgreSQL 16, имитатор ИИ `fakeai`.
Исходные результаты — в [`results/`](results/). Цифры ниже округлены.

## Нагрузка: 100 пользователей, 3 группы по 30 с

| Группа | Запросов | p99 | max | Ошибок |
|---|---:|---:|---:|---:|
| 1. 100 обучающихся заполняют карточки | ~4 800 | ~60 мс | ~0,4 с | 0 |
| 2. Смешанные роли (80 обучающихся, 15 преподавателей, 5 админов) | ~4 400 | ~60 мс | ~70 мс | 0 |
| 3. Пик: одновременный приём вызова и сдача | ~2 600 | ~230 мс | ~0,3 с | 0 |

Запись в БД — около 130 подтверждённых операций в секунду. Требования ТЗ выполнены: отклик
≤ 2 с, не меньше 20 сессий, не меньше 100 записей/с.

## Обрыв сети (ТЗ: ≤ 30 с без потери данных)

| Сценарий | Восстановление |
|---|---|
| Обрыв сети клиента на 5 / 15 / 29 с | ~0,5 / ~0,5 / ~0,8 с |
| Обрыв 29 с, клиент повторяет с паузами SPA (1–10 с) | ~10 с |
| «Чёрная дыра» на 15 с | ~0,2 с |
| Перезапуск PostgreSQL на 10 с | ~0,5 с |

Во всех сценариях каждое событие записано ровно один раз, черновик совпадает с состоянием
клиента, пропущенные сообщения WebSocket дочитаны, сдача и оценка работают.
