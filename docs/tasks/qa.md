# Задачи: QA (тестирование продукта и качества моделей)

Владелец: QA. Твоя зона — три вещи: (1) окружение и приёмка
docker-образов, (2) тесты продукта по контрактам и на стенде, (3) данные и разметка,
по которым мы выбираем и оцениваем модели (вместе с питонистом — `ml-research.md`).

Ничего из этого не требует писать код сервиса. Требует: аккуратность, Bruno/curl,
таблицы, слух и голос (датасеты), и упорство в воспроизведении багов.

Читать перед стартом: `docs/voice-mode.md` (что строим), `docs/tasks/README.md`
(этапы и DoD), спеки `contracts/openapi/*.yaml` (это язык, на котором описано
поведение — все тесты пишутся «по спеке»).

## QA-01 — Окружение *(первым делом, до образа от питониста)*

Установить на свой ноутбук (нужно ≥ 16 ГБ RAM, ≥ 40 ГБ свободного диска):
- **Docker Desktop** (Windows: включить WSL2; macOS — обычный). Проверка: `docker run hello-world`.
  В настройках выделить Docker ≥ 12 ГБ RAM и ≥ 6 CPU — иначе Ollama не поднимет модель.
- **git** + доступ к репозиторию; `git clone …`, ветка `main`.
- **Python 3.11** (для bench-скриптов и `tools/smoke.py` вне контейнера) + `pip install uv`.
- **Node.js 20+** — запускать фронт на моках: `cd frontend && npm i && npm run dev`.
- **Bruno** (open-source API-клиент, импортирует OpenAPI) — для ручных запросов к ai-service и go-core.
- **Audacity** — запись и нарезка аудио для датасетов.
- **Ollama** (натив или из compose) и заранее скачанные модели (интернет нужен один раз;
  список актуализирует питонист в `ai-service/config/models.yaml`):
  ```bash
  ollama pull qwen2.5:3b-instruct-q4_K_M
  ollama pull qwen2.5:7b-instruct-q4_K_M
  ollama pull qwen3:4b
  ollama pull gemma3:4b
  ```
- Браузеры: **Chrome, Firefox, Яндекс.Браузер** — все три нужны по ТЗ; в каждом
  проверить, что микрофон разрешён для `https://localhost:*`.
- Гарнитура с микрофоном (любая) + отдельно проверить встроенный микрофон ноутбука.

Приёмка: `docker compose -f ai-service/compose.ai.yaml up` с `ENGINES=mock` (когда
придёт образ `ai-service:stage1`) → `curl localhost:8000/v1/health` отвечает.
До этого: `docker run erikvl87/languagetool` поднимается и `curl …/v2/languages` отвечает,
`ollama run qwen2.5:3b-instruct-q4_K_M "привет"` отвечает по-русски.

## QA-04 — Датасет речи (STT) и mock-аудио *(как можно раньше — блокирует ML-01)*

**а) Датасет для выбора STT** — самая ценная твоя работа в начале работы.
- Список 25 фраз в `ai-service/bench/data/stt/phrases.csv` (`id, text, category`),
  категории: адреса с числами; телефоны; ФИО; протокольные фразы («Служба сто
  двенадцать, оператор двести двадцать семь, слушаю»); описания происшествий;
  короткие ответы («да», «понял», «повторите, пожалуйста»). Числа в `text` — цифрами
  (как должно распознаться): «улица Ленина дом 14 корпус 2 подъезд 3 этаж 5».
- 4 диктора из команды (мужские и женские голоса, разный темп). Записать **через
  наш фронт** (страница pre-flight/панель разговора в dev-режиме сохраняет webm —
  попросить фронтендера сделать кнопку «скачать запись» в dev-панели) — так формат
  1:1 с продом. Резерв — Audacity, wav 16 кГц mono.
- Именование `s<диктор>_p<фраза>.webm`; `manifest.csv`: `file, speaker, text_ref,
  category, noise, duration_ms`.
- Шум: записать 1 минуту фона офиса/улицы в `bench/data/noise/`; 10 файлов «тишина
  и шум без речи» (для проверки, что модель не выдумывает слова).
- Согласие дикторов на использование голоса в проекте — строкой в `bench/data/stt/README.md`.

**б) Mock-аудио для фронта** — 12–15 коротких реплик заявителя (`public/mock-audio/
caller_01.wav …`): «Алло! У нас дым из квартиры!», «Третий подъезд, пятый этаж»,
«Не знаю, я не вижу», «Алло? Вы меня слышите?», «Спасибо, жду». Один голос, в панике.

## QA-05 — Сценарии диалога для bench и ручное тестирование заявителя *(этапы 2–3)*

- `bench/data/dialog/scenarios.json` — 8 сценариев по категориям (пожар, ДТП, медицина,
  газ, преступление, ЧП на воде, обрушение, бытовой конфликт) с брифом: 2 факта
  `volunteer`, 3 `on_request` с hints, 1 `never` (ловушка), 2 `unknowns`. Пишется
  вместе с питонистом — он знает формат, ты — предметную область (памятка АРМ-112,
  билеты из `~/Downloads`).
- `operator_scripts.json` — 3 линии поведения оператора × 6 реплик: «хороший»
  (полный протокол), «плохой» (не спросил адрес, «ждите», грубость), «хаотичный».
- Ручные сессии (этап 3): 10 диалогов текстом через фронт с каждым кандидатом-моделью,
  слепая оценка реплик 1–5 в таблице `bench/reports/caller_human.csv`
  (`model_hidden_id, turn, naturalness, in_character, comment`). Отдельно отмечать:
  выдал факт без вопроса; выдумал; ответил не по-русски; попрощался рано.

## QA-06 — Golden set и разметка для судьи *(с этапа 2; сначала ≥ 30, к финалу ≥ 50)*

- Рубрика `bench/data/golden/RUBRIC.md` (вместе с лидом): что такое `present /
  partial / missing` для факта; `done / partial / missed` для пункта чек-листа;
  шкала общего балла 0–100 с якорями (100 — всё есть и точно; 70 — потерян один
  второстепенный факт; 40 — потерян ключевой факт или домысел; 0 — не по теме).
- Сбор попыток: команда играет студентов (по 3 роли: хороший / средний / плохой)
  на 4–5 сценариях → попытки с карточкой и транскриптом экспортирует питонист в
  `attempts.jsonl` / `transcripts.jsonl`; ты добавляешь синтетические варианты
  (убрать факт, вставить домысел, вставить «ждите»).
- Разметка в `labels.csv`: `attempt_id, fact_id|check_id, status, evidence_turn,
  score_text, score_dialogue, needs_review, labeler`. 15 попыток размечают двое —
  фиксируем процент совпадений (если < 75 % — рубрика непонятна, чиним её, не данные).

## QA-07 — Функциональное тестирование *(каждый образ / каждый этап)*

**ai-service (по образам `stage1`, `stage2`, `stage3`, `release`)** — прогон `tools/smoke.py`
(питонист даёт команду в README) + Bruno-негативы + чек-лист:
- health `ok` после старта ≤ 90 с; `degraded` при остановленном Ollama (`docker stop ollama`) — и сервис **не падает**;
- STT: 5 файлов из датасета → текст с числами цифрами; тишина → `no_speech=true`; 61 с → 413; mp3 → 415;
- диалог текстом: 6-ходовой сценарий «хороший оператор» → факты раскрываются по вопросам,
  `never` не звучит, `should_end` после «помощь направлена»; Ollama остановлен → `fallback=true`, 200;
- диалог аудио: реальная реплика с гарнитуры → транскрипт верный, ответ озвучен, файл есть в volume;
- TTS: фразы с «д. 14», «кв. 7», «ДТП», «8 916…» — на слух без «дэ», «ка-вэ»;
- jobs grammar/semantic/dialogue → callback приходит в `callback_sink` за ожидаемое время;
  повтор `request_id` → один результат; `/v1/queue` показывает глубину;
- перезапуск контейнера посреди задачи → задача теряется (ожидаемо), сервис поднимается, дубля нет.

**Frontend на моках (этап 2)** — чек-лист голосового УХ в трёх браузерах:
- pre-flight: запрос микрофона, уровень, «проверить звук»; отказ → предложен текст;
- PTT: удержание Ctrl/кнопки — запись, отпустил — отправка; пока заявитель говорит,
  запись невозможна; 60 с — автостоп; реплика < 0.3 с не отправляется;
- транскрипт, повторное прослушивание (счётчик `replay` растёт), «положить трубку»;
- `caller_busy` (мок каждый 8-й) → тост, повтор той же реплики работает;
- F5 посреди разговора → транскрипт восстановлен, номер хода не сбился;
- результат: плитка «Разговор», чек-лист с подсветкой реплик, метрики, транскрипт с аудио;
- редактор сценария: бриф и чек-лист редактируются, валидация id, генерация с прогрессом;
- в DevTools → Network у студента **нет** `keyFacts`, `dialogue`-брифа, `expectedDialogue`, эталона.

**Интеграция на go-core (этапы 3–4)** — сценарий DoD из `README.md` целиком, плюс:
- два студента одновременно в одном занятии — транскрипты не перепутаны;
- преподаватель видит live-реплики ≤ 3 с после хода;
- вес `dialogue` = 0 при выключенном голосе — плитки нет, итог сходится с весами;
- override балла с причиной → запись в аудите (проверяет лид по БД).

**Регрессионный чек-лист** (короткий, 15 минут) — прогоняется перед каждым этапом и
перед демо; живёт в `docs/qa/regression.md`.

## QA-08 — Нефункциональные требования ТЗ *(этап 4)*

- **Нагрузка диалогов**: `bench/scripts/load_dialog.py` (питонист) — 1/2/4/8
  одновременных диалогов; фиксируем p50/p95 хода и момент, когда начинается 503.
  Число «одновременных голосовых студентов на CPU» — в `model-selection.md`.
- **Отклик ≤ 2 с при 100 пользователях** для не-AI эндпоинтов — простой k6-скрипт
  (лид даст) на `GET /attempts/{id}`, `PUT /draft`, `POST /events`.
- **Обрыв сети ≤ 30 с без потери данных**: отключить Wi-Fi на 20 с посреди заполнения
  карточки и посреди хода диалога → после восстановления черновик и транскрипт целы,
  событий-дублей нет (проверяет лид по `attempt_events.client_seq`).
- **Офлайн**: полностью отключить интернет на стенде → всё работает (генерация, STT, TTS).
- **Устойчивость**: `docker kill ai-service` во время хода → фронт показал «заявитель
  не отвечает», после рестарта ход повторяется; `docker kill ollama` → fallback-реплики.
- **20 одновременных сессий**: 20 вкладок/2 машины, занятие запущено, все получили попытки.
