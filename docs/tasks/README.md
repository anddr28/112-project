Правила:
- `make contracts-lint` — зелёный перед любым MR, трогающим `contracts/`.
- Кодоген: `make generate` (Go/Python/TS). Сгенерированное руками не правится.
- Изменение спеки — отдельным MR с пометкой `[contract]`; ревьюят оба конца
  (Go + Python или Go + Frontend). Молча «доработать поле» нельзя.
- Пока Go не готов — фронт живёт на моках по этой же спеке, Python тестируется
  напрямую (Bruno/curl/скрипты), QA — на docker-образе Python без ядра.

## Definition of Done для демо (M4)

Сценарий, который прогоняется на защите и должен работать «с одного дубля»:

1. Преподаватель: генерирует сценарий «Пожар в жилом доме, сложность 2» → через
   ≤ 2 мин получает легенду, бриф заявителя, эталонную карточку, чек-лист →
   правит одну строку → валидирует.
2. Преподаватель: создаёт занятие с голосом (`voice.enabled`), назначает студента, запускает.
3. Студент: видит входящий, «Принять», слышит заявителя, проходит pre-flight микрофона.
4. Студент: 4–6 ходов диалога голосом (PTT), параллельно заполняет карточку, «Сохранить».
5. Преподаватель в это время видит live: статус, транскрипт, поля.
6. Через ≤ 60 с — результат: 5 слоёв, чек-лист разговора с подсветкой реплик,
   метрики речи, рекомендации; преподаватель добавляет комментарий.
7. Отказ микрофона (эмулируем запретом в браузере) → студент переходит на текстовый ввод, попытка не ломается.
8. Всё это — на ноутбуке без интернета (`docker compose up` из образов).

## Рабочий процесс

- Ветки `feat/<area>-<short>`, MR в `main`, ревью лида; мелкие правки документации — без ревью.
- Ежедневный синк 15 минут (время — в чате): что сделано / что блокирует / что до завтра.
- Баги — issue в GitLab по шаблону из `qa.md`, критичность S1–S4.
- Секреты — только в `.env` (в `.gitignore`); `.env.example` — в репозитории.
- Модели и веса — не в git: `ai-service/models/` в `.gitignore`, скачиваются
  скриптом `make models-pull` (нужен интернет один раз) и запекаются в образ.
